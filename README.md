# Jenkins and Kubernetes DevOps Lab

A practical home lab demonstrating application deployment from GitHub
to Kubernetes through Jenkins, with manifest validation and HTTP testing.

## Current deployment workflow

1. Change the application HTML or Kubernetes manifests.
2. Commit and push the changes to GitHub.
3. Start the Jenkins deployment job.
4. Jenkins checks out the repository.
5. Kubernetes validates the generated manifests using a server-side dry run.
6. Jenkins applies the configuration and waits for the rollout.
7. An HTTP smoke test checks that the application returns the expected content.

Pipeline execution is currently started manually with Build Now.

## Kubernetes application

The application runs as a Deployment with three replicas.

A NodePort Service provides access to NGINX. The HTML page is mounted
from a ConfigMap generated by Kustomize.

When the HTML changes, Kustomize generates a new ConfigMap name based
on its content. The updated reference in the Deployment triggers a
rolling update.

All replicas currently run on one Kubernetes node. This lab does not
provide node-level high availability.

## Jenkins deployment stages

- Check tools
- Validate manifests
- Deploy to Kubernetes
- HTTP smoke test

The pipeline uses server-side dry-run validation, waits for the
Deployment rollout and fails if the HTTP response does not contain
the expected text.

## Access and credentials

- Jenkins accesses Kubernetes through the `jenkins-deployer` ServiceAccount.
- RBAC permissions are scoped to the `devops-lab` namespace.
- The kubeconfig is stored as a Jenkins Secret file with ID `k3s-devops-lab`.
- Credentials and private keys must not be committed to this repository.
- The lab token was requested with a 24-hour lifetime and requires renewal.
- Jenkins is accessed through Caddy over HTTPS.
- The Jenkins HTTP listener is restricted to localhost.

## Troubleshooting example

A misspelled image tag caused a Pod to enter ImagePullBackOff and the
Deployment to exceed its progress deadline.

The issue was diagnosed using Pod status, Deployment details and events.
The image tag was corrected in Git, then deployed again through Jenkins.

This showed that manifest validation does not verify whether an image
tag exists in the registry.
